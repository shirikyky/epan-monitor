# epan-monitor

ניטור חיצוני לאתר **https://everypaintinghasaname.com** (פרויקט "לכל ציור יש שם").

## למה זה קיים

לאתר יש שני שומרים שרצים **על השרת עצמו**:

| שומר | תדירות | תפקיד |
|---|---|---|
| `epan-tunnel-watch.sh` | כל 15 דק' | מחזיר את השרת / מנהרת Cloudflare אם נפלו |
| `epan-uptime-check.sh` | כל 10 דק' | בודק שהאתר מוגש, שה-DNS תקין ושאין פניות שלא נשלחו |

החולשה שלהם: **אם השרת כולו נופל — הם לא רצים**, ואיש לא מקבל התראה.

הריפו הזה סוגר את הפינה הזו: הבדיקה רצה **מהענן של GitHub**, כל 10 דקות.

## איך זה עובד

- האתר בריא → **שקט מוחלט**, אין רעש.
- האתר לא מגיב / התוכן לא שלנו / ה-DNS הוסט → **נפתח Issue** עם תווית `uptime`,
  ו-GitHub שולח עליו מייל לבעלת הריפו.
- האתר חוזר → ה-Issue **נסגר מעצמו** עם תגובה.

בדיקה ידנית: לשונית **Actions** → `uptime` → **Run workflow**.

## מה נבדק

1. `HTTP 200` על דף הבית
2. שהתוכן הוא שלנו (סימן `assets/app.js` — קיים רק באתר החדש)
3. שהדומיין מפענח לכתובת של Cloudflare ולא למקום אחר

## תחזוקה

GitHub מכבה workflows מתוזמנים בריפו ללא פעילות 60 יום, ולכן ה-workflow
מבצע **commit קטן אחד בחודש** (`.keepalive`) כדי להישאר דרוך.

## הפעלה ראשונה

1. **Settings → Notifications** — לוודא שמייל על Issues פעיל.
2. אם רוצים התראה גם ב-SMS או כש-GitHub עצמו מושבת: להוסיף את הכתובת גם ב-
   [UptimeRobot](https://uptimerobot.com) (חינם, בודק כל 5 דקות).
